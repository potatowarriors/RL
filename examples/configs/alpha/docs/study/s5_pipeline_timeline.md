그림: [`s5_pipeline_timeline_20261022.png`](s5_pipeline_timeline_20261022.png) (10:30~19:00, display step 46~53, target 46~53).
다시 그리기: `python examples/configs/alpha/tools/plot_pipeline_timeline.py <run_dir> "<YYYY-MM-DD HH:MM>" <out.png> [gpu_csv]`
(원자료: TensorBoard `timing/*` 의 step 종료 시각과 구간 길이, `rollout_groups.jsonl` 의 그룹 완료 시각, nvidia-smi 표본 CSV).

이 문서는 관측 기록이다. 원인 판정과 선택지는 `KNOWN_ISSUES.md` 2026-10-22 항목 "롤아웃 엔진이 2-step 마다 비고…" 이 정본이다.
처음 쓴 해석("나이 1 + 통째 물결 기동이 원인, 유휴 25~30%")은 블라인드 독립 검증에서 **반박**됐고 아래는 정정본이다.

## 줄 읽는 법

| 줄 | 뜻 | 원자료 |
|---|---|---|
| sub1 학습기 | step 하나를 구간으로 나눈 것: 대기(회색, 버퍼에 배치가 찰 때까지) → 준비(노랑) → 학습(빨강) → refit(주황) → 검증(보라) → 저장(갈색). 점선은 step 종료 | `timing/train/*`, `timing/validation/*` |
| main1 롤아웃 물결 (짝수·홀수 target) | target 하나의 생성 활동. 점 무늬 = 기동(refit 종료 시각으로 추정)부터 첫 그룹 완료까지, 파랑 = 완료가 쌓여 128번째 kept 에 이르기까지, 남색 = 그 뒤 꼬리. **한 target 의 파랑 구간에는 첫 배치(253 그룹)와 그 뒤의 메움 라운드가 모두 들어 있다** — 그림만으로 둘을 가를 수 없다 | `rollout_groups.jsonl` `time` |
| main1 검증 생성 | 검증 256문제 생성 (같은 엔진을 쓴다) | `timing/validation/total_validation_time` |
| 5분당 완료 그룹 수 | 엔진 출력의 대리 지표. 빨간 상자 = 10분 넘게 완료 0. **완료 0 ≠ GPU 유휴**: 새 물결은 기동 뒤 첫 완료까지 13~47분이 걸리고 그동안 GPU 는 바쁘다 | `rollout_groups.jsonl` |
| main1 GPU util 실측 | 17:16 부터 30초 표본 (초록 선, 0~100%) | `$JOBTMP/gpu_util_main1.csv` |

## 그림에서 확인되는 사실

1. step 시간은 20분과 93~118분이 번갈아 나오고, 긴 step 의 대기(`exposed_generation`)가 75~89분이다.
2. target 둘이 8~16분 차이로 완료된다 (47/48: 12:26·12:41, 49/50: 14:40·14:56, 51/52: 17:10·17:19).
3. 완료 0 구간(23~35분) 안에서 실제 GPU 0% 는 2~12분이다 (step 46·48·50·52 각각 2.1·6.1·4.2·12.3분; 17:18~17:30 은 표본으로 확인). 전체로는 **벽시계의 7.6~8.5%**.
4. 각 target 의 첫 배치(253 그룹)는 keep 0.41 에서 88~120 kept 만 내고, 메움 라운드는 첫 배치의 마지막 그룹이 끝나야 기동한다. 선행 target 의 메움은 후행 target 의 4,048 시퀀스 물결 뒤에 줄을 서서 첫 완료까지 16~39분이 걸린다 (후행은 0.7~4.5분). 그래서 target 쌍이 같이 끝난다.

## 의미 (정정본)

- 쌍 잠김을 만드는 것은 DAPO 수집기의 **첫 배치 크기와 통째 예약 구조**이고, 나이 1 은 그 결과를 0% 유휴로 바꾸는 문이다. 검증자의 실제 수집기 시뮬레이션에서 나이 1·DAPO 끔은 교대도 유휴도 없었다.
- 나이 2 만으로는 유휴 8.3% → 3.5%, step −6.5% 이고 묵음이 1.9배가 된다. 첫 배치를 탈락률에 맞게 키우는 것(overprovision 125 → 200)이 설정만으로 −5~13% 이고 묵음은 그대로다.
- 2바퀴의 4회 업데이트는 학습 구간을 17 → 약 24분으로 늘려 유휴를 몇 분 키운다 (시뮬: T 15/20/25분 → 유휴 5.5/7.3/11.8%).
