# alpha 런 기동·재개 절차

이 skill 은 **순서**만 담는다. 수치·기전·사고 서사는 링크한 문서가 정본이다 — 여기에 복사하지 않는다.
경로는 리포 루트 기준이고 `alpha/` 는 `examples/configs/alpha/` 다. 승인·검증·독립 검토 규칙의 정본은 사용자 공통 원칙 `/home/work/vidsearch/.claude-config/CLAUDE.md`.

순서가 중요한 이유: 지금까지의 런 손실은 대부분 "알던 점검을 기동 전에 하지 않은 것"에서 나왔다 — 루트 디스크 spill(10-13),
호스트 메모리 OOM(10-20), 재개 즉시 종료(10-13), 기동 뒤에야 한 검토(10-20 DAPO 교착, 3시간). 1단계는 GPU 를 잡지 않으므로 승인 없이 한다.

## 1. 기동 전 점검 (읽기·계산만)

1. **`alpha/docs/STATUS.md` "진행 중"** — 다른 세션의 런과 GPU 사용을 확인한다. 같은 워킹트리를 여러 세션이 쓴다.
2. **레시피 검사** — `alpha/tools/check_alpha_recipe.py <recipe> [override …]` 가 ERROR 0. 드라이버 venv 로 돌린다 (명령은 스크립트 docstring).
   블렌드를 바꾸면 `data.train.data_path=<blend>` 를 붙여 다시 돌린다.
3. **게이트 재실행 여부** — 체크포인트·브리지·플러그인·레시피를 바꿨으면 `alpha/docs/GATES.md` "재실행 조건" 표로 판정한다.
4. **자원 계산** — 프롬프트 수·생성 상한·CP 가 바뀌면 기동 전에 계산해 보고에 넣는다.
   - 호스트 메모리 = 학습 배치 객체 크기 × CP 랭크 수 (+ 복사본) — `alpha/docs/KNOWN_ISSUES.md` "256 프롬프트 · 48K 런이 main1 호스트 메모리 부족" 절.
   - Ray 객체 spill 과 루트 디스크 — 큰 배치는 `df -h /` 여유를 확인한다. 기준은 같은 문서 "`main2r6` … spill" 절과 `alpha/CLAUDE.md` 함정 표 10-13·10-20.
5. **재개라면** — 프롬프트 수·GBS·스텝 수를 바꿔 재개할 때 네 가지를 먼저 본다: 스케줄러 플래그 · 에폭 클램프 · 데이터로더 위치 · 후속 자동화의
   "정상 종료" 판정 (`alpha/docs/KNOWN_ISSUES.md` "프롬프트 수를 64 → 256 으로 바꿔 … 재개" 절). 재개 첫 학습 스텝의 메모리 함정은 함정 표 10-11.
6. **W&B** — 실제 학습 런만 올린다. 스모크·게이트·속도 시험은 `WANDB=0` (`alpha/CLAUDE.md` 레시피 규약).
7. **독립 검토 대상인지** — 처음 조합으로 띄우는 런, 배치·스케줄·필터 구조를 바꾸는 레시피, 런에 들어가는 본체 패치가 해당한다
   (공통 원칙 "독립 검토"). 해당하면 **보고 전에** 컨텍스트를 공유하지 않는 새 에이전트(Agent 도구 `model: opus`, `effort: xhigh`)에게
   실제 설정값·관측 사실·답할 질문을 주고 읽기 전용 적대적 검토를 받는다. BLOCKER·HIGH 는 반영한 뒤 보고한다.

## 2. 보고하고 승인받는다

기동·중단·재시작은 보충 스모크·게이트를 포함해 승인 대상이다. 보고는 결론을 먼저 쓰고 아래 항목을 표로 담는다.

| 항목 | 내용 |
|---|---|
| 런 | campaign / tag, 레시피, 오버라이드 전부, 데이터, 시작 체크포인트 |
| 자원 | GPU·노드, 예상 시간, 4번 계산 결과 |
| 점검 결과 | 검사기 ERROR 수, 게이트 판정, 재개 네 가지, 독립 검토 요약(심각도·조치) |
| 중단 조건 | 무엇을 보면 멈추고 다시 보고하는지 |

"진행해" 는 그 보고의 계획에만 해당한다. 점검이 깨지면 우회 플래그·임계 완화로 넘기지 않고 멈춰서 다시 보고한다 (공통 원칙 "검증" 1).

## 3. 기동

- Gym 런은 `alpha/runs/launch.sh <campaign> <tag> [override …]` 로 띄운다. 환경변수(RECIPE·DATA·VAL·CKPT·WANDB·EXTRA_ENV)는 스크립트 머리말이 정본이다.
  실행기가 다른 런 액터 · 남은 Gym 서버 · GPU 점유를 스스로 검사하고 `runs.log` 에 기동 줄을 남긴다.
- 스모크·게이트는 `alpha/CLAUDE.md` Quick Commands 와 `alpha/docs/GATES.md` 의 명령을 그대로 쓴다 (`clean_run.sh` · `</dev/null` · `CUDA_VISIBLE_DEVICES` 금지).
- 실행 중인 잡이 import 하는 코드와 `launch.sh` 는 편집하지 않는다 — 잡이 죽거나 bash 가 바뀐 오프셋을 읽는다.

## 4. 기동 직후 확인

- `runs.log` 의 기동 줄(commit · overrides)이 보고한 계획과 같은지 본다.
- **첫 학습 스텝 통과**를 확인한다. 재개 런은 특히 그렇다.
- 정체 감시는 로그 mtime 이 아니라 **스텝 번호**로 한다. 멈췄으면 엔진별 생성 토큰 증가량으로 낙오와 교착을 가른다 (함정 표 10-13).
- rc 0 으로 바로 끝났으면 정상 종료로 단정하지 않는다 — 최종 체크포인트가 있는지 확인한다.

## 5. 기록

- `alpha/docs/STATUS.md` "진행 중" 행에 런 이름 · 시작 시각 · commit · 오버라이드 · 로그 경로를 쓰고 바로 커밋·push 한다 (명시 pathspec).
- 사고가 나면 서사는 `alpha/docs/KNOWN_ISSUES.md` 에, `alpha/CLAUDE.md` 함정 표에는 한 줄만 쓴다.
